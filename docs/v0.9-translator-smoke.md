# WiiCompiled Web v0.9 — First translated instruction execution

## Goal

Cross the boundary from hand-written memory adapter tests to actual C++ emitted by the upstream WiiCompiled PowerPC translator.

## What the build does

1. Checks out the upstream WiiCompiled translator at a pinned commit (see the workflow).
2. Builds the upstream `Translator.Core` as a dependency of a small .NET harness.
3. Constructs a synthetic, eight-byte PowerPC program in memory:
   - `addi r3, r3, 7`
   - `blr`
4. Runs the upstream `FunctionTranslator` over those instruction bytes and writes the generated C++ into the build workspace.
5. Compiles that generated C++ together with a small ABI wrapper using Emscripten.
6. Runs the generated function in the browser's WebAssembly module with r3 initialized to 35 and checks that it becomes 42.

No DOL, game dump, game-specific manifest, Nintendo code, or game assets are used.

## Scope and limitations

This validates one real translator-generated function and the generated-code CPU-context ABI. It does not translate a game, prove full Wii memory/MMIO behavior, or connect the full upstream runtime. The existing browser memory helper remains a separate prototype until generated loads/stores are tested against the exact upstream helper ABI.

The upstream project is GPL-3.0. The workflow consumes its source at a pinned revision and does not copy its source files into this repository. Any future redistribution incorporating upstream code must follow its license and retain the required notices.
